# Как сделать, чтобы заявитель видел свою заявку

## Часть 1. Механизмы видимости в 2.1

## Механизмы видимости внутреннего документа в 1С:ДО 2.1

| # | Механизм | Есть в 2.1 | Что даёт | Где настраивается |
|---|---|---|---|---|
| 1 | **Рабочая группа документа** | Да — разд. «Рабочие группы объектов» ([ИТС ПРОФ 2.1, 20.7](https://its.1c.ru/db/docprof21/content/148/hdoc)) | Список пользователей/ролей, которые видят документ. **Если рабочая группа заполнена, права считаются только по ней — политики доступа и права папок не применяются** | Закладка/поле «Рабочая группа» в карточке документа; галочка «Изменение» = право на правку, по умолчанию только чтение ([1С-БИТ](https://www.1cbit.ru/blog/nastroyka-prav-dostupa-v-1s-dokumentooborot-opisanie-i-instruktsiya/)) |
| 1а | **Автоведение состава** | Да — флажок на **виде документа** *«Автоматически вести состав рабочей группы»* (точное написание — **проверить** в вашем релизе) | В группу автоматически попадают автор, авторы и исполнители процессов по документу, пользователи из реквизитов (ответственный, зарегистрировал, утвердил) | НСИ → Виды внутренних документов → карточка вида. Рядом — «Заполнение рабочей группы является обязательным» ([1С-КПД](https://1c-kpd.ru/knowledge/prava-dostupa/rabochaya-gruppa-v-1s-dokumentooborot/)) |
| 2 | **Права папок** внутренних документов | Да ([ИТС 20.6](https://its.1c.ru/db/docprof21/content/147/hdoc)) | Дополнительно **сужают** доступ; запрет приоритетнее разрешения. Но при заполненной рабочей группе не работают | Карточка папки → настройка прав (название команды — **проверить**) |
| 3 | **Политики доступа / профили (полномочия)** | Да | Политики режут по разрезам: виды документов, организации, гриф, группы контрагентов. Профили/полномочия дают роли — «что вообще можно делать». **Разреза «автор документа» в политиках нет** — сделать «автор видит свой документ» политикой нельзя | Настройка → Права доступа → Политики доступа / Профили групп доступа (**проверить** названия) |
| 4 | **Гриф доступа** | Да | Может закрыть документ **и от автора**: если грифа нет в политике автора, он документ не увидит. При заполненной рабочей группе гриф на видимость не влияет (следствие приоритета рабочей группы — **проверить** на стенде) | Реквизит «Гриф доступа» в карточке; разрешённые грифы — в политике |
| 5 | **Задача «Ознакомление»** | Да | Исполнитель задачи получает доступ **на чтение** предмета («права по касанию»). Автору задача не адресуется, поэтому сама по себе проблему не решает; можно добавить автора отдельным ознакомителем. Сохраняется ли доступ после выполнения задачи — **проверить** | Шаблон процесса / маршрут в шаблоне вида документа |
| 6 | **Как автор ищет** | Да | Список «Мои документы» ([ИТС 4.2](https://its.1c.ru/db/docprof21/content/38/hdoc)); быстрые отборы и поиск в списке «Внутренние документы»; обработка «Поиск документов и файлов»; полнотекстовый поиск; «Избранное» и «История» ([ИнфоСофт](https://is1c.ru/about/pc/article/10-sposobov-nayti-i-ne-poteryat-dokument-v-1s-dokumentooborot-2-1/)). Точный состав «Моих документов» и имя реквизита автора («Автор» / «Подготовил») — **проверить**: открытого текста ИТС я не получил | Списки раздела «Документы и файлы» |
| 7 | **Уведомление без прав** | Да | Уведомления шлются по e-mail/всплывающим окном со ссылкой вида `e1cib/data/...` ([ИТС гл. 17](https://its.1c.ru/db/doccorp21/content/781/hdoc)). Письмо уходит, но без прав ссылка документ не откроет. Формулировку отказа **не подтвердил** источниками — не выдумываю | Настройка → Уведомления |

### Предупреждение про 3.0
Автоматическая выдача прав по задачам «из коробки», правила автозаполнения групп доступа из пользовательского режима и опция «Расширять» права со связанных документов — это **редакция 3.0**; в 2.1 их нет, там папки + политики + рабочие группы ([ИнфоСофт: различия 2.1 и 3.0](https://is1c.ru/about/pc/article/razlichiya-1s-dokumentooborot-versii-2-1-i-3-0/)). Гибкое автозаполнение рабочих групп алгоритмом в 2.1 закрывается сторонним расширением ([«Автозаполняемые рабочие группы»](https://www.doc-lvv.ru/blog/1076406)) — то есть штатное автоведение в 2.1 фиксированное, не программируемое.

### Что сделать (прямой ответ)
1. В карточке **вида внутреннего документа «Заявка на доступ к ресурсам»** включить флажок автоматического ведения состава рабочей группы — тогда автор и участники процессов попадают в группу сами.
2. Для уже созданных заявок дозаполнить рабочую группу массово (обработка «Групповое изменение реквизитов»).
3. Проверить, что папка заявок не содержит явного запрета, и что гриф доступа на заявках либо не ставится, либо перекрывается рабочей группой.
4. Автору показать заявки через отбор по автору в списке «Внутренние документы» и «Мои документы»; при желании — добавить в конец маршрута ознакомление автора.
5. Обязательно проверить результат на тестовой базе отчётом проверки настроенных прав — приоритет рабочей группы над политиками я подтвердил только вторичными источниками ([doc-lvv](https://www.doc-lvv.ru/prava-dostupa-v-1s-dokumentooborot-21), [ИнфоСтарт](https://infostart.ru/1c/articles/2718393/)); полный текст ИТС закрыт авторизацией.

## Часть 2. Пошаговая настройка

## Короткий ответ

Заявку не видно, потому что в 1С:ДО 2.1 у автора нет автоматических прав на свой документ: доступ даёт либо рабочая группа документа, либо папка/политика. Решение: у **вида** внутреннего документа «Заявка на доступ к ресурсам» включить автоматическое ведение состава рабочей группы — тогда автор попадает в неё сам [НАСТРОЙКА]. Для уже поданных заявок рабочую группу дозаполнить массово. Готовой галочки «автор видит своё» в 2.1 нет.

## Перед настройкой — 4 проверки

☐ **Есть ли у вас право менять настройки.** Откройте НСИ → Виды внутренних документов и попробуйте открыть карточку нужного вида. Если поля серые/не открывается — нужен администратор.

☐ **Есть ли тестовая копия базы.** Все шаги сначала делаются в копии. Если копии нет — просите администратора сделать её до начала.

☐ **Кто сейчас в рабочей группе.** Откройте 2–3 уже поданные заявки и посмотрите поле/закладку «Рабочая группа»: пусто или там есть люди. Если заполнено — права считаются **только** по ней, папки и политики не действуют.

☐ **Приходит ли автору письмо о заявке.** Спросите у автора. Письмо со ссылкой может приходить, а прав всё равно не быть — это разные вещи (уведомление ≠ доступ).

## Настройка по шагам

1. **Включить автоведение рабочей группы** [НАСТРОЙКА] [КОРОБКА]
   Открыть: НСИ → Виды внутренних документов → карточка вида «Заявка на доступ к ресурсам».
   Сделать: поставить флажок «Автоматически вести состав рабочей группы» (точное написание — *проверить в своей базе*, в разных релизах формулировка отличается). Записать и закрыть.
   Результат: создаём тестовую заявку — в её рабочей группе автоматически появляется автор и участники процесса.

2. **Проверить флажок обязательности** [НАСТРОЙКА]
   Там же, рядом, есть «Заполнение рабочей группы является обязательным». Его включать не обязательно; смотрите, чтобы он не мешал сохранению заявки.

3. **Дозаполнить старые заявки** [НАСТРОЙКА]
   Открыть: обработка «Групповое изменение реквизитов» (доступна администратору).
   Сделать: отобрать внутренние документы нужного вида и добавить авторов в рабочую группу. Если обработка табличную часть «Рабочая группа» не поддерживает в вашем релизе — *проверить*; тогда либо открывать заявки вручную, либо это [ДОРАБОТКА].
   Результат: в старых заявках в рабочей группе есть автор.

4. **Проверить папку и гриф** [НАСТРОЙКА]
   Открыть: папку, где лежат заявки, → настройка прав доступа (название команды *проверить в своей базе*).
   Сделать: убедиться, что нет явного **запрета** на группу пользователей-авторов. Запрет сильнее разрешения.
   Открыть карточку заявки: реквизит «Гриф доступа». Если гриф стоит и у автора его нет в политике — он документ не увидит. Проще всего гриф на заявках не ставить.
   Результат: в папке нет запретов, гриф пустой или разрешён автору.

5. **Показать автору, где искать** [КОРОБКА]
   Раздел «Документы и файлы» → список «Внутренние документы» → отбор по автору; плюс список «Мои документы». Точный состав «Моих документов» и имя реквизита автора («Автор» либо «Подготовил») — *проверить в своей базе*.

6. **По желанию — ознакомление автора** [НАСТРОЙКА]
   В шаблоне процесса добавить в конец маршрута задачу «Ознакомление» на автора: исполнитель задачи получает доступ на чтение. Сохраняется ли доступ после выполнения задачи — *проверить*.

## Проверка результата

1. В **тестовой копии** попросите администратора создать тестового пользователя-заявителя (или используйте свою вторую учётку) — 1 мин.
2. Войдите под ним и подайте тестовую заявку — 1 мин.
3. Не выходя, откройте «Мои документы» и «Внутренние документы» с отбором по автору. Заявка должна быть видна и открываться — 1 мин.
4. Откройте саму заявку и посмотрите рабочую группу: там должен быть автор — 30 сек.
5. Вернитесь под свою учётку и проверьте отчёт по настроенным правам доступа (в разделе прав доступа; *проверить название*) — 1,5 мин.

Главное: смотреть **под учётной записью автора**. Под своей вы почти наверняка видите документ по другим правам, и проверка ничего не докажет.

## Если не сработало

| Симптом | Вероятная причина | Что смотреть |
|---|---|---|
| Заявка не видна, рабочая группа пустая | Флажок автоведения не включён или включён после создания заявки | Карточка вида документа; создать новую тестовую заявку |
| Письмо пришло, а по ссылке нет прав | Уведомление и права — независимы: письмо ушло, доступ не выдан | Рабочая группа этой конкретной заявки; добавить автора вручную |
| Автор в рабочей группе, но заявку не открывает | Гриф доступа не разрешён автору либо права кэшированы | Реквизит «Гриф доступа»; перезайти в программу; отчёт по правам |
| Видит в списке, но не может править | В рабочей группе не стоит галочка «Изменение» — по умолчанию только чтение | Строка автора в рабочей группе |
| Новые заявки видны, старые нет | Автоведение работает только вперёд | Групповое изменение реквизитов по старым документам |
| Не видит ни один автор, ни в одном виде | Запрет на папке или политика доступа не даёт вид документа | Права папки заявок; политики доступа профиля автора |
| Заявка появилась, но её содержимое/файлы недоступны | Права на файлы считаются отдельно | Открыть вложение под автором |

## Что это НЕ решает

- **Гибкую логику** «кому именно показывать» — в 2.1 автоведение фиксированное, программировать состав группы нельзя без стороннего расширения [ДОРАБОТКА].
- **Автовыдачу прав по задачам** и опцию «расширять» права со связанных документов — это редакция 3.0, в 2.1 их нет.
- **Показ автору чужих заявок** его отдела — рабочая группа даёт доступ поимённо, «автор» как разрез в политиках отсутствует.
- **Ситуацию с грифом**: если гриф обязателен по регламенту, конфликт «гриф против рабочей группы» надо проверять на стенде — приоритет рабочей группы подтверждён только вторичными источниками, не текстом ИТС.
- **Красивый список «мои заявки»** одной кнопкой — пока это отбор в общем списке; отдельный список — [ДОРАБОТКА].
- **Права на файлы и печатные формы** — считаются отдельно от карточки документа.
