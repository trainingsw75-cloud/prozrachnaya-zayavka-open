# Пакет на рассмотрение: проект «Прозрачная заявка»

**Что это.** Один документ, с которым вы идёте к руководству. Внутри — маршрут внесения, готовые тексты на подпись, три формулировки просьб, проверяемая доказательная база и то, что нужно вести после положительного решения.

**Рамка.** Задача внесения — не показать всё, что у вас есть, а провести один документ через пять кабинетов так, чтобы в конце появилась строка в протоколе: формулировка, фамилия ответственного, дата. Всё остальное — приложения.

**Условные обозначения (единые для всего пакета):**

| Маркер | Что означает |
|---|---|
| **[КОРОБКА]** | Работает штатными средствами системы, без программирования. Нужно только начать пользоваться |
| **[НАСТРОЙКА]** | Делает администратор 1С:Документооборот штатными средствами: права, шаблоны, уведомления. Денег обычно не требует, требует его времени |
| **[ДОРАБОТКА]** | Требуется программист или подрядчик: техническое задание, часы, договор, деньги |
| **[ПРОВЕРИТЬ]** | Факт не подтверждён. Подтверждается письменно у профильного специалиста или по внутренним документам — не берётся из этого текста |

**Правовая оговорка (действует по всему пакету).** Формулировки про регламент, локальный нормативный акт, персональные данные, коммерческую тайну и грифы вы не утверждаете и не трактуете. Они выносятся на юридическую службу и на службу информационной безопасности. В своих документах пишите: «проект порядка», «предлагается вынести на юридическую службу».

**Правило данных.** В пакете намеренно нет ни одной цифры, ни одной фамилии и ни одного номера приказа. Все числа вы получаете замером (Часть 1, раздел 1.3) и вписываете сами. Число без указанного способа получения на защите разбирают первым.

Три листа: выжимка, перечень стадий, бланк протокола. Журнал замера держите при себе — показываете, когда спросят «откуда цифры».

### Чего не показывать вообще

| Что | Почему |
|---|---|
| Черновую рабочую тетрадь | Это ваша кухня, а не документ |
| Интерактивную доску решений с кнопками «Отклонить / Отложить» | Руководитель увидит свою роль расписанной заранее и решит, что за него уже всё решили. Доска — рабочий инструмент **после** положительного решения |
| Оформительские материалы, палитру, макеты | Отвлекают от предмета |

| Документы второй волны (Часть 5) | Пока не принято решение по первой, они читаются как «она хочет перестроить процесс целиком» |

### Правило 1–3–30

- **1 страница** — служебная записка. Её читает руководитель.
- **3 страницы** — выжимка, перечень стадий, схема маршрута. Их читают на совещании.
- **30 минут чтения** — проект технического задания (для ИТ) и проект порядка (для юрслужбы). Только этим двум адресатам, персонально, с фразой «нужна ваша оценка вот этого раздела».

**[ПРОВЕРИТЬ]** Объём считайте по фактическому числу страниц при печати (предварительный просмотр), а не по размеру файла: руководитель считает страницы.

## Часть 1. Маршрут внесения — кому, в каком порядке, с чем

### 1.1. Правило маршрута

Порядок жёсткий: снизу вверх, без прыжков через голову. Каждая ступень — не «одобрение», а **снятие одного возражения**, которое иначе прозвучит наверху и убьёт проект.

На каждой ступени просите не одобрения, а **одну визу или одну фразу в письме**: «возражений нет» или «замечания в приложении». Эти три-четыре строки — ваш главный козырь наверху. К руководству заходить только после того, как ИБ и ИТ дали хоть что-то письменно.

### 1.3. Замер: 5 рабочих дней, три числа

Без этого дальше не идти.

**Лист учёта обращений — если нужен подробный замер времени:**

```
ЛИСТ УЧЁТА ОБРАЩЕНИЙ «ЧТО С МОЕЙ ЗАЯВКОЙ»
Период наблюдения: с __.__.20__ по __.__.20__

Дата | Время | Канал (телефон / почта / лично) | Номер заявки | Минут потрачено
-----|-------|--------------------------------|--------------|----------------
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |
     |       |                                |              |

ИТОГО за период: обращений ____ , минут ____
```

**Единая нотация (используется во всём пакете — других обозначений не вводить):**

| Обозначение | Что это | Как получить |
|---|---|---|
| **N** | Заявок за период (в пересчёте на месяц) | Журнал замера или выгрузка из 1С за 3 месяца |
| **O** | Обращений «где моя заявка» за период | Журнал замера |
| **K** | Обращений на одну заявку | O ÷ N |
| **t** | Минут на одно обращение | Замер по часам |
| **T** | Средний срок прохождения заявки, рабочих дней | Сумма (дата исполнения − дата подачи) ÷ N |
| **D** | Доля заявок, вышедших за срок, % | n просроченных ÷ N × 100 |
| **Д** | Доля обращений, которую снимут уведомления | Пока не измерено — брать не больше 0,5 |
| **C** | Стоимость часа работ подрядчика | Только у экономической службы |
| **Cр** | Стоимость рабочего часа сотрудника | Только у экономической службы |
| **H** | Часы доработки | Только оценка ИТ или подрядчика |

**Формулы:**

- Экономия времени, часов в месяц: **Э = N × K × t × Д ÷ 60**
- Отклонение от норматива: **ΔT = T фактический − T нормативный**
- Срок окупаемости доработки, месяцев: **P = (H × C) ÷ (Э × Cр)**

Обязательная фраза в записке и вслух на совещании: «расчёт выполнен по данным замера за период с ___ по ___; методику прошу проверить экономическую службу».

### 1.4. Чем и как передавать материалы

| Способ | Плюсы | Минусы | Когда применять |
|---|---|---|---|
| **Распечатка** | Читают. Ложится в папку. Визу подписывают прямо на листе | Только текст, максимум 3 листа | Записка, выжимка, схема, бланк протокола |
| **Файлы по почте** | Быстро, остаётся след отправки | Вложения-архивы и веб-страницы почта часто режет; могут переслать дальше без пояснений | Техническое задание и проект порядка — в обычном офисном формате документа |
| **Папка на общем диске** | Один адрес, версии не расползаются, из внутренней сети не выходит | Никто не зайдёт, пока прямо не скажете; нужны права | Полные пакеты для ИТ и ИБ |
| **Ссылка на внутренний портал** | Всегда актуальная версия | Внешние ссылки — вопрос к ИБ, сами не решайте; ссылка на личное облако = гарантированный конфликт | Только если внутренний портал есть и ИБ не возражает |

### 2.3. Перечень стадий и тексты уведомлений **[КОРОБКА]**

Самая дешёвая часть проекта: перечень стадий и тексты писем стоят ноль рублей и утверждаются одним решением. Тексты составлены так, чтобы не раскрывать ни состав согласующих, ни содержание заявки. **Итоговый состав сведений утверждает служба ИБ.**

| № | Стадия | Когда наступает |
|---|---|---|
| 1 | Принята к рассмотрению | Заявка зарегистрирована |
| 2 | На согласовании | Ушла согласующим лицам |
| 3 | Требуется уточнение | Возвращена заявителю за недостающими сведениями |
| 4 | Согласована, исполняется | Согласование завершено, доступ оформляется |
| 5 | Исполнена | Доступ предоставлен |
| 6 | Отклонена | Принято решение об отказе |

```
1. ПРИНЯТА К РАССМОТРЕНИЮ
Здравствуйте! Ваша заявка на доступ к ресурсам № ____ от __.__.____
принята к рассмотрению. Ориентировочный срок рассмотрения —
до __.__.____. О смене стадии вы получите отдельное уведомление.
Отвечать на это письмо не требуется.

2. НА СОГЛАСОВАНИИ
Здравствуйте! Заявка № ____ от __.__.____ находится на стадии

3. ТРЕБУЕТСЯ УТОЧНЕНИЕ

_____________________________________________________________.

До получения ответа рассмотрение заявки приостановлено.

4. СОГЛАСОВАНА, ИСПОЛНЯЕТСЯ
Здравствуйте! Заявка № ____ от __.__.____ согласована и передана

5. ИСПОЛНЕНА

```

**[ПРОВЕРИТЬ] [НАСТРОЙКА]** В 1С:Документооборот КОРП ред. 2.1 есть штатный механизм уведомлений с настраиваемыми текстами (глава 17 «Уведомления» официальной документации — см. Приложение). Применимость к вашей конкретной конфигурации подтверждает сопровождение 1С, не вы. Ваша формулировка на совещании: «часть задачи, возможно, решается штатными средствами системы, прошу коллег из ИТ это подтвердить».

**[ДОРАБОТКА]** Отдельная страница, где заявитель сам смотрит стадию без письма и без входа в систему, — это программирование. Её оценивает ИТ.

> **Внимание: конфликт вариантов.** В подготовительных материалах есть **два разных перечня из шести стадий**: приведённый выше (стадии рассмотрения, состав согласующих скрыт) и перечень по этапам маршрута из раздела 2.7 (*Принята → Проверка комплектности → Согласование службы информационной безопасности → Решение владельца ресурса → Настройка доступа → Выполнена / Отклонена*). Второй вариант раскрывает заявителю, какие службы участвуют в согласовании. **До подачи выберите один перечень и используйте его во всех документах пакета.** Выбор второго варианта обязательно согласуется со службой ИБ.

## Часть 3. Три просьбы — что именно просить у руководства

Больше трёх просьб = ноль решений. Выберите один набор и не смешивайте.

| Вариант | Когда применять | Три просьбы |
|---|---|---|
| **А. Денег нет, ИТ загружены** (самый проходной) | Бюджет закрыт, план ИТ забит | 1. Утвердить перечень стадий и тексты уведомлений — решение стоит ноль рублей.<br>2. Назначить контролёра сроков из числа действующих работников, без новой ставки.<br>3. Поручить ИТ оценить трудоёмкость — только оценить, не делать |
| **Б. Есть своё сопровождение 1С** | Администратор доступен, вопрос в приоритете | 1. Включить работы в план подразделения ИТ на ____ квартал.<br>2. Назначить ответственного за процесс целиком и срок пробного применения на ограниченном круге заявителей (одно подразделение, один месяц) |

Формулировка на совещании, если просят «а можно всё сразу»: «прошу зафиксировать три пункта; остальное вернём отдельным вопросом после оценки ИТ».

## Часть 5. Что внедрять срочно при объёме — срочная пятёрка

> Эта часть — **вторая волна**. На первое совещание не выносится: пока не принято решение по первой подаче, она читается как попытка перестроить процесс целиком. Все утверждения о возможностях 1С:Документооборот здесь помечены **[ПРОВЕРИТЬ]** и подтверждаются письменно администратором или подрядчиком.

### 5.1. Переменные роста — заполнить один раз, 30 минут

| Обозн. | Что это | Где взять | Ваше значение |
|---|---|---|---|
| **N** | заявок на доступ в месяц | реестр 1С:ДО за 3 месяца, среднее | ___ |
| **R** | ресурсов (систем, папок, программ) в среднем в одной заявке | вручную посмотреть 20 заявок | ___ |
| **S** | сколько согласующих проходит одна заявка | карточка процесса | ___ |
| **t** | минут ручной работы на одну заявку | замер по секундомеру на 5 заявках | ___ |
| **C** | стоимость часа исполнителя, руб. | бухгалтерия или планово-экономический отдел. **На глаз не оценивать** | ___ |
| **H / U** | приёмов / увольнений и переводов в месяц | кадровая служба | ___ / ___ |

**Формулы роста:**

- Ручная работа, часов в месяц = **N × t ÷ 60**; в деньгах = **N × t ÷ 60 × C**
- Число согласований в месяц = **N × R × S**. Здесь не сложение, а умножение: добавили один ресурс в заявку — объём вырос на всё число согласующих. Это и есть главная опасность роста.
- «Мёртвые» доступы за год = **U × R × 12 × k**, где *k* — доля вовремя не отозванных. Пока автоотзыва нет, считайте k = 1 — до первой сверки.

### 5.2. Пороги: что ломается при 10 / 50 / 200 / 500 заявках в месяц

Принцип: **до ~50 заявок процесс держится на людях, после — только на правилах.**

**До 10 заявок в месяц**

| Что ломается | Признак | Что сделать заранее |
|---|---|---|
| Ничего критичного | «Всё помню, всех знаю» | Записать процесс на бумаге, пока он простой: реестр заявок с обязательными полями (кто, что, зачем, до какой даты), один вид документа на все заявки |

**50 заявок в месяц (2–3 в рабочий день)**

| Что ломается | Почему | Что сделать заранее |
|---|---|---|
| Ручной запуск процесса | 50 × t минут только на «завести и запустить». При t = 15 мин это 12,5 ч/мес (**пример условный**) | Шаблон процесса + автозапуск по виду документа **[НАСТРОЙКА] [ПРОВЕРИТЬ]** |
| Письма заявителю руками | В пиковые дни их перестают писать — возвращается исходная боль | Автоуведомления по шаблонам при смене этапа **[НАСТРОЙКА] [ПРОВЕРИТЬ]** |
| В маршруте стоит человек, а не роль | Один в отпуске — очередь встала, и никто не знает, у кого | Перевести маршрут на роли, назначить замещающих |
| Контроль «на глазок» | 50 заявок ещё просматриваются глазами, но уже с ошибками | Отчёт «просроченные задачи» раз в неделю, один ответственный |

**200 заявок в месяц (около 10 в день)**

| Что ломается | Почему | Что сделать заранее |
|---|---|---|

| Согласование каждого ресурса по отдельности | N × R × S действий. При R = 4 и S = 3 это 2 400 согласований в месяц (**пример условный**) | Типовые наборы доступов по должностям (5.4) |
| Нет замещающих | Один отпуск = десятки зависших заявок | У каждой роли не меньше одного замещающего, проверка перед отпуском |
| Лицензии и веб-клиент | Растёт число одновременно работающих | Посчитать пик одновременных сеансов, запросить у подрядчика расчёт лицензий **[ПРОВЕРИТЬ]**. Это статья бюджета — её нельзя обнаружить в декабре |

| Один контролёр | Не тянет; процесс держится на одном человеке — точка отказа | Роль контролёра + замещающий + отчёты вместо ручного просмотра |
| Архив как узкое место | Массовые операции конкурируют за то же время | 5.6: что требует штрихкода, а что делается телефоном |

### 5.3. Срочная пятёрка

Ровно пять, а не пятнадцать: наверх защищается короткий список, а внедрять нужно то, что убирает **умножение**, а не единичное неудобство. Выдуманных часов здесь нет — указан только класс работ; часы запрашиваются письмом (5.8.5).

| № | Мера | Что даёт | Если не сделать | Маркер | Кто делает |
|---|---|---|---|---|---|
| 1 | **Шаблон процесса + автозапуск заявки** | Убирает N × t на «завести и запустить» | При N = 200 запуск заявок становится отдельной полставки (**пример условный**: 200 × 10 мин = 33 ч/мес) | **[НАСТРОЙКА] [ПРОВЕРИТЬ]** | Администратор 1С; постановку задачи пишете вы |
| 2 | **Роли вместо фамилий в маршруте + обязательные замещающие** | Единственная защита от отпусков и увольнений внутри маршрута | Каждая кадровая перестановка требует ручной правки маршрутов; заявки виснут без видимой причины | **[НАСТРОЙКА] [ПРОВЕРИТЬ]** | Администратор 1С + владелец процесса |
| 3 | **Срок действия доступа как обязательное поле** | Единственный пункт, который **невозможно** сделать задним числом | Через год — массив доступов без владельца и без срока; самая частая претензия при проверке ИБ | Поле **[НАСТРОЙКА]**, напоминание **[ПРОВЕРИТЬ]** | Администратор 1С; политику сроков утверждает ИБ |
| 4 | **Автоуведомления заявителю + страница-трекер** | Ваша исходная боль; единственный пункт из пяти, который виден заявителю, — защищается лучше всего | С ростом объёма растёт поток звонков «а где моя заявка» — нагрузка, которой нет ни в одном отчёте | Уведомления **[НАСТРОЙКА] [ПРОВЕРИТЬ]**, трекер **[ДОРАБОТКА]** | Администратор; трекер — подрядчик по вашему ТЗ |
| 5 | **Реестр + еженедельный отчёт по просрочкам** | Без измерения вы узнаёте о проблеме от руководителя, а не из отчёта | Нет доказательной базы для запроса ресурсов наверх | **[КОРОБКА]** / **[НАСТРОЙКА] [ПРОВЕРИТЬ]** | Контролёр процесса, еженедельно, 30 минут |

**Что проверить по каждому пункту:** по п. 2 — как в вашей сборке назначается замещающий и что происходит с задачей, если исполнитель уволен; по п. 5 — хватает ли штатных отчётов и выгрузки в таблицу.

### 5.4. Типовые наборы доступов по должностям

**Почему поштучно нельзя.** Число согласований = N × R × S. Поштучный подход умножает объём на R. Набор убирает R: согласуется **один** пакет вместо R позиций. **Пример условный:** при N = 200, R = 4, S = 3 поштучно — 2 400 согласований в месяц; наборами — 600, то есть на 75 % меньше.

1. Матрица «должность → перечень ресурсов → уровень (чтение / изменение) → основание». Ведёт служба ИБ вместе с владельцами ресурсов, утверждается приказом № ___ от __.__.____.
2. Матрица утверждается **один раз в год**: спорят о составе доступов один раз в год, а не 200 раз в месяц.
3. Заявка при приёме на работу = выбрали должность → пакет подставился целиком → согласуется как одно целое. Всё сверх пакета идёт по старому длинному маршруту — таких заявок будут единицы.

**[ПРОВЕРИТЬ]** Механизмы, на которых такую задачу обычно строят: шаблоны процессов, автоподстановки исполнителей, шаблоны документов, дополнительные реквизиты и условия маршрутизации. Есть ли они все в вашей сборке и хватит ли их — подтверждает подрядчик письменно (вопрос 1 в 5.8.5).

### 5.5. Автоотзыв при увольнении и переводе — самое опасное место

**Почему опаснее всего.** Все прочие сбои задерживают работу. Этот оставляет **действующий доступ у человека, который больше не должен его иметь**. Заявки растут пропорционально, а невыявленные висящие доступы **накапливаются**: за год U × R × 12. При U = 5 и R = 4 это 240 доступов за год (**пример условный**). Ни один не проявит себя, пока не случится инцидент.

**Перевод опаснее увольнения.** При увольнении учётную запись отключают целиком, и ошибка заметна. При переводе учётная запись живёт, человек просто копит права двух должностей — и это не отслеживает никто.

| Ситуация | Что делать |
|---|---|
| Обмен с кадровой системой есть | Кадровое событие → автоматически создаётся задача «Отозвать доступы» по всем активным записям сотрудника со сроком «последний рабочий день». **[ПРОВЕРИТЬ]** у администратора: настроен ли обмен, какие справочники в него входят, как часто он идёт |
| Обмена нет | Ручной регламент: еженедельный список от кадров → сверка с реестром активных доступов → задачи на отзыв со сроком 1 рабочий день → акт сверки как доказательство при проверке → пункт «Отзыв доступов» в обходном листе → раз в квартал сплошная сверка. Полный текст — 5.8.4 |

### 5.6. Массовые операции архива: где нужен штрихкод и ТСД, а где хватит телефона

*ТСД — терминал сбора данных, переносной сканер с экраном, с которым ходят между стеллажами.*

| Операция | От чего зависит трудоёмкость | Штрихкод / ТСД | Минимально достаточное решение |
|---|---|---|---|
| **Приём фонда** | Число единиц хранения за раз | Штрихкод — да | Печать штрихкодов средствами 1С:ДО. Наличие штрихкодирования в вашей сборке — **[ПРОВЕРИТЬ]** |
| **Передача дел, закрытие, передача в архив** | Размер партии | Штрихкод — да, ТСД — нет | Работа с номенклатурой дел штатными средствами — **[ПРОВЕРИТЬ]**, в каком объёме это есть у вас |
| **Инвентаризация** | Сплошной обход полок | **Здесь ТСД даёт максимальный эффект** | Поддержка ТСД именно в ред. 2.1 **не проверена [ПРОВЕРИТЬ]**. Если штатной поддержки нет — сканер, работающий как клавиатура, либо выгрузка и загрузка файла |
| **Выдача десятков дел** | Число операций «выдал / вернул» | Штрихкод — да, ТСД — избыточен | Стационарный сканер на стойке выдачи. Сканирование камерой телефона — **[ПРОВЕРИТЬ]** |
| **Разовые сверки, фотофиксация** | Единичные операции | Нет | Телефон |

**Правило разделения:** ТСД нужен там, где человек **ходит**. Там, где человек **стоит за столом**, хватает стационарного сканера или телефона. Покупать ТСД до пилотной инвентаризации — типичная ошибка бюджета.

### 5.7. Пять метрик раннего предупреждения

Все пять снимаются из реестра еженедельно выгрузкой в таблицу, доработок не требуют.

| № | Метрика | Как считать | О чём предупреждает | Порог тревоги (**условный, утвердить**) |
|---|---|---|---|---|
| 1 | Возраст самой старой открытой заявки | сегодня минус дата создания, максимум по незакрытым | Срабатывает раньше среднего срока: среднее ещё хорошее, а «хвост» уже растёт | Больше двух нормативных сроков |
| 2 | Приток против закрытия | поступило ÷ закрыто за неделю | Больше 1 две недели подряд — очередь растёт, срыв неизбежен | > 1 две недели подряд |
| 3 | Концентрация на одном согласующем | доля открытых задач у самого загруженного | Показывает узкое место до того, как человек уйдёт в отпуск | Больше 30 % задач у одного |
| 4 | Доля ручных вмешательств | заявки с перезапуском, ручной пересылкой или перепиской мимо системы ÷ N | Люди начали обходить систему | Рост два периода подряд |
| 5 | Доля доступов без срока и просроченных | (без даты окончания + просроченные) ÷ всего активных | Единственная метрика, растущая молча: жалоб не будет никогда | Любой рост |

Пороги утверждает владелец процесса и закрепляет в регламенте. Неутверждённая метрика превращается в справку «для сведения».

1. Назначение
1.1. Регламент устанавливает порядок выявления и отзыва доступов к

2.1. Активный доступ — предоставленный работнику и не отозванный доступ к

## Часть 6. Реестр решений: колонки, формат, ритм сопровождения

Смысл реестра: через полгода человек, впервые открывший файл, отвечает на четыре вопроса — **что решили, кто решил, когда, сделано ли**. Поэтому решение и его исполнение живут в одной строке, а не в двух разных документах.

*Реестр — обычная таблица Excel. CSV — та же таблица, сохранённая простым текстом: она открывается на любом компьютере и не портится со временем, поэтому её держат как архивную копию.*

### 6.1. Готовая шапка **[КОРОБКА]**

Разделитель `;` — так файл корректно откроется в русской версии Excel.

```
№;Блок;Формулировка пункта;Что предлагалось;Решение;Кто решил (ФИО);Должность;Дата решения;Основание (документ);Ссылка на документ-основание;Условие доработки;Ответственный за исполнение;Соисполнители;Срок плановый;Статус исполнения;Дата фактическая;Чем подтверждено;Трудозатраты/ресурс;Зависит от пункта №;Риск при неисполнении;Дата пересмотра (для отложенных);Комментарий;Кто изменил строку и когда
```

**Образец строки — только формат, содержательных данных нет:**

```
7;Письма-уведомления;<суть пункта одним предложением>;<вариант А> / <вариант Б>;Доработать;<ФИО>;<должность>;__.__.____;Протокол № ___ от __.__.____;<путь к файлу или № в 1С>;<что именно изменить>;<ФИО>;<подразделение>;__.__.____;В работе;;;<___ ч>;<№ пункта>;<что будет, если не сделать>;;<комментарий>;<ФИО> __.__.____
```

### 6.2. Что означает каждая колонка

Знаком **•** отмечены двенадцать обязательных колонок. Если двадцать три колонки пугают — начните с обязательных; но добавлять колонку в готовый файл дороже, чем оставить её пустой сейчас.

| Колонка | Зачем нужна | Как заполнять |
|---|---|---|
| **• №** | Сквозной неизменяемый номер пункта | Присвоили один раз — не перенумеровывать никогда, даже если пункт отклонён. На этот номер ссылаются протоколы и задачи |
| **• Блок** | Раздел проекта | Закрытый список: Регламент / Трекер / Письма-уведомления / Роли и права / Маршрут согласования / Приёмка |
| **• Формулировка пункта** | Суть вопроса | Одно предложение, без слов «улучшить» и «оптимизировать». Образец построения: «Заявитель получает письмо при переходе заявки на каждую стадию» |
| **Что предлагалось** | Память о вариантах | 1–2 строки. Через полгода спасает от повторного обсуждения по кругу |
| **• Решение** | Ядро реестра | Ровно 4 значения: **Использовать / Доработать / Отклонить / Отложить**. В Excel закрепить: «Данные → Проверка данных → Список» — тогда «наверное» вписать не получится **[НАСТРОЙКА, 2 минуты своими силами]** |
| **• Кто решил (ФИО)** | Персональная ответственность | Не «руководство», а конкретный человек. Пустое поле = решения нет |
| **• Должность** | Проверка полномочий | Чтобы через полгода было видно: решал тот, кто вправе |
| **• Дата решения** | Точка отсчёта срока | Формат ДД.ММ.ГГГГ |
| **• Основание (документ)** | След решения в делопроизводстве | «Протокол № ___ от __.__.____», «Служебная записка № ___», «Резолюция на заявке № ___» |
| **Ссылка на документ-основание** | Возможность проверить | Регистрационный номер в 1С:ДО, кликаемая ссылка или путь в сетевой папке. Без этого поля реестр — пересказ |
| **Условие доработки** | Только для статуса «Доработать» | Что именно изменить, чтобы пункт стал «Использовать». Формулировка проверяемая |
| **• Ответственный за исполнение** | Кто делает | Один человек, не отдел. Нет исполнителя — пункт не «в работе», а «отложен» |
| **Соисполнители** | Кого придётся привлекать | ИТ, юрслужба, защита информации, подрядчик |
| **• Срок плановый** | Дата, а не «по мере возможности» | ДД.ММ.ГГГГ |
| **• Статус исполнения** | Главный столбец для отчёта | Закрытый список: Не начато / В работе / На проверке / Выполнено / Отменено / Отложено |
| **Дата фактическая** | Факт против плана | Ставится в день закрытия, задним числом не правится |
| **• Чем подтверждено** | Доказательство вместо слова | Номер задачи, скриншот, ссылка на утверждённый файл, номер приказа |
| **Трудозатраты/ресурс** | Цена решения | «___ ч своими силами» / «___ ч подрядчика» / «ресурсов не требует» |
| **Зависит от пункта №** | Порядок работ | Показывает, почему пункт стоит: он ждёт другой |
| **Риск при неисполнении** | Аргумент на защите | Одна строка: что будет, если не сделать |
| **Дата пересмотра** | Спасает отложенные пункты | Обязательна при статусе «Отложить». Пункт без даты пересмотра теряется навсегда |
| **Комментарий** | Контекст | Возражения, оговорки, кто был против |
| **• Кто изменил строку и когда** | История правок | ФИО + дата последней правки |

**[ПРОВЕРИТЬ] Персональные данные.** В реестре будут ФИО и должности сотрудников. Где хранить файл, кому давать доступ, можно ли передавать его подрядчику — решает не архив. Вопрос письменно вынести на юрслужбу и на службу защиты информации **до** того, как файл уйдёт за пределы вашего подразделения.

### 6.3. Форматы передачи решений: сравнение и рекомендация

| Формат | Кому подходит | Что видно | Что теряется | Как хранить | Как отчитываться |
|---|---|---|---|---|---|
| **Печатный протокол с подписями** | Руководителю, который даёт полномочия и ресурсы | Факт решения, кто подписал, дата | Ход исполнения: бумага не меняется, а проект меняется | В деле по номенклатуре, **срок хранения — [ПРОВЕРИТЬ] у делопроизводства** | Как основание: «протокол № ___ от __.__.____» |
| **TXT (выгрузка текстом)** | Ни для чего как основной документ | Решения сплошным текстом | Сортировка, фильтр, статусы, сроки | Только как черновой след рядом с реестром | Практически никак |
| **Excel + копия в CSV** | Вам, куратору, ИТ, подрядчику | Решение + исполнитель + срок + статус + подтверждение сразу | Подписи и полномочия: файл сам ничего не утверждает | Один файл в одном месте, версии по 6.6 | Фильтр по статусу — и сводка готова |
| **Доска в браузере** | Рабочей группе в момент обсуждения | Варианты, комментарии, кто что выбрал | Ничего, если после совещания выгрузить в файл. Всё, если доска осталась на одном компьютере | Как инструмент обсуждения, не как хранилище | Доской не отчитываются — отчитываются выгрузкой |
| **Задача в 1С:ДО** | Исполнителям и контролёру | Срок, исполнитель, ход, просрочка | Логика решения: «почему так решили» в задаче не хранится | В системе, по её правилам | Штатными отчётами **[ПРОВЕРИТЬ], какие доступны вам** |

**Рекомендация — одна.** Основной формат: **реестр решений в Excel, копия в CSV как архивная.** Остальное вспомогательное:

- **печатный протокол** — единственный источник полномочий: он превращает предложения в поручения; реестр ссылается на него колонкой «Основание»;
- **1С:ДО** — среда исполнения: строка со статусом «Использовать» и назначенным исполнителем становится задачей;
- **доска в браузере** — среда выработки решений на совещании; после совещания выгружается и закрывается;
- **TXT** — промежуточный экспорт, самостоятельной ценности не имеет.

Почему именно реестр: он фильтруется и считается, печатается на одну страницу для руководителя, переживает смену людей и не зависит от прав доступа в 1С — его можно отдать подрядчику, у которого доступа в систему нет.

### 6.6. Имена файлов и версии **[КОРОБКА]**

**Шаблон имени:** `ГГГГ-ММ-ДД_Прозрачная-заявка_<ЧТО-ЭТО>_v<NN>_<СТАТУС>.<расширение>`
**Пример вида:** `2026-08-14_Прозрачная-заявка_Реестр-решений_v03_UTV.xlsx`

| Правило | Пояснение |
|---|---|
| Дата в начале и только в формате ГГГГ-ММ-ДД | Файлы сами выстраиваются по хронологии |
| Без пробелов — дефис или подчёркивание | Пробелы ломают ссылки и пути |
| Версия двузначная: `v01`, `v02` | Не «2», не «2.1.новый» |
| Запрещённые слова: финал, финальный, итог, новый, последний, испр, правка, ок, ok | Именно они порождают «пять финальных версий» |
| Статус — одно из трёх: `DRAFT`, `NAPROVERKE`, `UTV` | Утверждённый файл больше не редактируется — правки идут в новую версию |
| Папки: `01 Действующее` / `02 В работе` / `03 Входящие от смежников` / `99 Архив` | В «01» — ровно один файл каждого вида. Всё, что перестало быть действующим, уходит в архив в тот же день |
| Несколько авторов — инициалы перед статусом | `..._v04_ИИ_DRAFT.xlsx` |
| Первый лист файла — «Титул» | Название, владелец, дата, номер версии, что изменилось (3 строки). Имя файла легко соврёт, титульный лист — нет |

**[ПРОВЕРИТЬ]** Если файл лежит в 1С:ДО и система сама хранит прежние версии, номер версии из имени можно убрать. Это вопрос № 4 из письма администратору (6.4); до ответа номер версии в имени оставляем.

## Часть 7. Отчёт на 30-й день — готовый шаблон

Отчёт формируется на основании реестра. Сведения, не подтверждённые колонкой «Чем подтверждено», в отчёт как выполненные не включаются.

1. Принято решений всего: ___, из них «Использовать»: ___, «Доработать»: ___,
   «Отклонить»: ___, «Отложить»: ___.
   (Берётся фильтром по колонке «Решение» в реестре.)

   3–5 строк:
   — пункт № ___ — ____________________, подтверждение: ____________________;

   — пункт № ___ — ____________________, подтверждение: ____________________.

3. Что не сделано и почему — пункты № ___, ___:

   юрслужбы на запрос от __.__.____»).
   Новый срок: «___» __________ 20___ г.

4. Что прошу у руководства — от одного до трёх пунктов, каждый со сроком
   и ценой:
   — ____________________, требуется ___ ч ресурса ____________,
     до «___» ______ 20___ г.;
   — ____________________, требуется решение ____________,
     до «___» ______ 20___ г.

5. Цифры периода — заполняются только измеренными значениями:
   — заявок за период: N = ___
   — обращений «на какой стадии моя заявка»: O = ___

**Откуда берутся цифры пункта 5.** N, T и D — из журнала регистрации заявок. O и t требуют измерения: **[КОРОБКА]** лист учёта обращений (Часть 1, раздел 1.3) на две недели — этого достаточно для первого отчёта. Цифра с указанным способом получения защищается; цифра без него — нет.

**Правило одной страницы.** Невыполненное показывается **раньше** выполненного и **всегда** с причиной и новой датой. Формулировка «в работе» без даты в отчёт не допускается.

| 2 | **Прыгнуть через голову.** Отправить сразу наверх — получить противника в лице непосредственного руководителя и заведующего архивом надолго | Строго по маршруту (Часть 1), каждому — его роль |

| 4 | **Просить всё сразу.** Пять просьб = ни одного решения | Ровно три из готового набора (Часть 3) |
| 5 | **Залезть на территорию ИТ и ИБ.** «Там работы на пару часов», «сделаем ссылку наружу» — и у вас два оппонента, которые разбираются лучше | Трудоёмкость спрашивать у ИТ, состав видимых полей — у ИБ. Пусть это будет их решение |
| 6 | **Превратить предложение в жалобу на коллег.** Одна фраза «у нас никто не следит за сроками» — и обсуждают уже не проект, а людей | Говорить только о процессе, никогда о подразделениях и фамилиях |
| 7 | **Выдать заготовки за готовую систему.** «Я уже всё сделала, осталось включить» вызывает два вопроса: «кто разрешил?» и «что вы делали в рабочее время?» | Формулировка «подготовлены проект технического задания и проект порядка — для рассмотрения специалистами» |
| 8 | **Уйти без протокола, ответственного и даты.** Это и есть то самое «спасибо, интересно» | Принести пустой бланк, проговорить решения вслух в конце встречи, на следующий день разослать протокол участникам |

**Девятое, бонусом:** не называйте это «моим проектом». Проект должен стать общим не позже второй ступени маршрута.

### Чего в пакете нет намеренно

Номеров приказов, фамилий, статистики, оценок в часах, стоимости, точных сроков услуг и любых чисел о вашей организации. Числовые примеры в Части 5 помечены «пример условный» — это арифметика по формулам, а не данные о вашем архиве. Все прочие цифры вы получаете замером и вписываете сами.
