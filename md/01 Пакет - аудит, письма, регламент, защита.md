развалится на первом же вопросе. Сводные списки того, что надо проверить и что
нельзя выдавать за факт, — в Приложениях П.2 и П.3.

| Вкладка | Что обычно пусто | Что положить | Эффект | Маркер |
|---|---|---|---|---|

| Файлы | только скан заявки | вторым файлом — **подтверждение выдачи** (скриншот прав, выгрузка из системы) | закрывает спор «а точно выдали?» | [КОРОБКА] |
| Категории | не используются | «Срочно», «Внешний подрядчик», «ПДн», «Требует отзыва» | список заявок читается с одного взгляда | [КОРОБКА] |
| Связи | пусто почти всегда | заявка ↔ заявка на отзыв; заявка ↔ кадровый документ-основание; заявка ↔ инцидент ИБ | вся история прав человека поднимается одной кнопкой | [КОРОБКА] |

> **Ссылки — важная оговорка.** Внутренняя ссылка вида `e1cib/...` открывается только у пользователя, у которого установлен и настроен клиент 1С. Для веб-клиента нужна http-ссылка на опубликованную базу. **До того как вставлять ссылку в шаблон письма — [ПРОВЕРИТЬ] на реальном получателе, что она у него открывается.** Иначе прозрачность превратится в новый повод для звонка.

| Настройки запуска | стартует автоматически или ждёт нажатия | включить автозапуск [ПРОВЕРИТЬ механизм в вашем релизе] | [НАСТРОЙКА] |

*[ГИПОТЕЗА] Перевод последовательного согласования (руководитель → ИБ) в параллельное сокращает общий срок. Величина сокращения — только по вашему замеру из шага 4: сложите фактическую длительность двух этапов и вычтите большую из них. Не заявлять цифру руководству до замера.*

### 2.4. Карточка задачи у согласующего

**Что видит:** предмет (саму заявку), автора, срок, историю предыдущих этапов, файлы.
**Что может:** выполнить с результатом (состав вариантов задаётся шаблоном — **[ПРОВЕРИТЬ] полный список в вашем**), написать комментарий, приложить файл, перенаправить задачу, принять к исполнению.
**Чего в общем случае нет:** отдельных кнопок «вернуть автору на доработку» и «запросить доп. информацию». Реализуется отрицательным результатом + условием маршрутизации на ветку доработки, либо созданием отдельного поручения. **[ПРОВЕРИТЬ] поведение именно в вашей схеме — не описывать в регламенте по памяти.**

**Главный дефект этапа:** комментарий при отрицательном результате не обязателен. Заявитель получает «Не согласовано» без причины и идёт звонить — вся прозрачность обнуляется.
**Закрыть:** сделать комментарий обязательным средствами шаблона [ПРОВЕРИТЬ, есть ли такая опция]; если опции нет — [ДОРАБОТКА]. Промежуточное решение без программиста: закрепить формулировку отказа в регламенте (текст в 4.2) и еженедельно выборочно проверять отказы без причины [КОРОБКА].

### 2.5. Карточка процесса «в работе»

Содержит: состояние (стартован / на паузе / завершён), список задач с плановыми и фактическими датами, историю, отображение хода по схеме.

**Вывод для проекта:** отдельную «панель статуса заявки» изобретать не нужно — она уже оплачена и работает. Задача — **вынести её наружу**: (1) ссылка на документ в письме заявителю, (2) обучение заявителя открывать вкладку процессов, (3) еженедельный отчёт контролёру. Всё три пункта — [КОРОБКА] / [НАСТРОЙКА], без программиста.

### 2.1. Блок прогресса: один параметр вместо шести копий

Во всех письмах используется вычисляемый многострочный параметр **`{БлокПрогресса}`**. Формируется один раз в коде (раздел 4), в шаблоны письма ставится одной строкой — иначе при изменении числа этапов придётся править шесть текстов.

**Рендер по умолчанию — ASCII** (гарантированно читается в Outlook, мобильной почте и в plain-text рассылке 1С):

```
Ход выполнения: [##---]  Шаг 2 из 5 — На согласовании

1. [x] Регистрация заявки — 15.07.2026
2. [>] Согласование руководителем — в работе с 15.07.2026, срок до 18.07.2026
3. [ ] Согласование владельца ресурса / информационной безопасности
4. [ ] Техническая настройка доступа
5. [ ] Доступ предоставлен

Обозначения: [x] выполнено · [>] в работе · [!] просрочено · [X] отклонено · [ ] ожидает
```

Эмодзи-вариант (зелёная/белая/красная плитка) допустим **только** в письмах, отправляемых как HTML в UTF-8, и только после проверки на реальных клиентах заказчика. В plain-text рассылке часть клиентов покажет «?». Решение зафиксировать до вёрстки шаблонов: **вариант письма — HTML / plain-text: ______**.

### 3.3. Три варианта реализации

| Вариант | Что получаем | Чего не получаем | Сложность | Оценка* |
|---|---|---|---|---|
| **1. Минимальный** | Типовые уведомления заявителю о старте, завершении и просрочке | Ни своего текста, ни шкалы, ни ссылки-трекера | [НАСТРОЙКА] | 0 ч программиста |

### 4.2. Формирование `{БлокПрогресса}` (для программиста)

Черновик, требует адаптации под имена объектов вашей базы.

```1c
// СостояниеШага[Ш] заполняется при сборке модели статуса:
// "Выполнен" / "ВРаботе" / "Просрочен" / "Отклонён" / "Ожидает"

Симв = Новый Соответствие;
Симв.Вставить("Выполнен",  "[x]");
Симв.Вставить("ВРаботе",   "[>]");
Симв.Вставить("Просрочен", "[!]");
Симв.Вставить("Отклонён",  "[X]");
Симв.Вставить("Ожидает",   "[ ]");

Полоса = "";
Строки = "";
Для Ш = 1 По ВсегоШагов Цикл
    Сост = СостояниеШага[Ш];
    Полоса = Полоса + ?(Сост = "Выполнен", "#", ?(Сост = "Ожидает", "-", "*"));
    Строки = Строки + Ш + ". " + Симв[Сост] + " " + НазваниеШага[Ш]
           + ?(ПустаяСтрока(ДатаШага[Ш]), "", " — " + ДатаШага[Ш]) + Символы.ПС;
КонецЦикла;

БлокПрогресса =
    "Ход выполнения: [" + Полоса + "]  Шаг " + НомерТекущегоШага
    + " из " + ВсегоШагов + " — " + НазваниеТекущегоЭтапа + Символы.ПС + Символы.ПС
    + Строки + Символы.ПС
    + "Обозначения: [x] выполнено · [>] в работе · [!] просрочено · [X] отклонено · [ ] ожидает";
```

### 4.3. Технические требования к отправке

| ☐ | Требование | Проверка до запуска |
|---|---|---|
| ☐ | Кодировка письма — UTF-8 | тестовое письмо не содержит «?» и «кракозябр» |
| ☐ | Формат согласован: HTML или plain-text | зафиксирован в ТЗ |
| ☐ | Моноширинное выравнивание блока прогресса в HTML | блок обёрнут в `<pre>` или задан `font-family: monospace` |
| ☐ | Проверка отображения в Outlook (десктоп), веб-почте, мобильной почте | 3 скриншота приложены к акту |
| ☐ | Тема письма не длиннее ~70 символов | иначе обрезается в списке писем |
| ☐ | Письма не попадают в спам | тест на 5 реальных адресах разных подразделений |
| ☐ | Ящик-отправитель не принимает ответы либо ответы читает архив | иначе ответы уходят в никуда |

## 5. УСЛОВИЯ МАРШРУТИЗАЦИИ

**Где:** раздел управления процессами → условия маршрутизации **[ПРОВЕРИТЬ путь в вашей базе]**. Режимы: конструктор, встроенный язык, комбинация условий. В режиме встроенного языка результат помещается в переменную `Результат` типа Булево; состав доступных переменных (`Предмет`, `ОбъектАдресации` и др.) **[ПРОВЕРИТЬ в вашем релизе]**. Код линейный — объявление собственных функций, как правило, недоступно.

| № | Условие | Когда срабатывает | Режим | Сложность |
|---|---|---|---|---|
| 1 | Тип доступа = «Полный» → добавить согласование ИБ | ветвление на этапе 3 | конструктор, если реквизит шапки; иначе код | [НАСТРОЙКА] / [ДОРАБОТКА] |
| 2 | Ресурс относится к архивным делам → согласование заведующего архивом | ветвление на этапе 3 | конструктор по виду документа | [НАСТРОЙКА] |
| 3 | Срок доступа бессрочный → утверждение директора | доп. этап | код | [ДОРАБОТКА] |
| 4 | Заявитель сам является руководителем → пропустить согласование руководителем | этап 2 | код | [ДОРАБОТКА] |

**Правила эксплуатации условий:**

| ☐ | Правило |
|---|---|
| ☐ | Название условия по формуле «ЕСЛИ … ТО …»: «ЕСЛИ тип доступа полный ТО согласование ИБ» |
| ☐ | В комментарии условия — дата изменения и ФИО автора правки |
| ☐ | Любая правка кода условия сначала на **тестовой копии базы**: ошибка останавливает процесс у всех пользователей одновременно |
| ☐ | Сравнение значений доп. реквизитов — **по ссылке на значение**, не по строке: переименование значения ломает сравнение по строке молча |
| ☐ | Отбор доп. реквизита — **по ссылке на свойство** (GUID), не по заголовку: заголовок переименуют, условие перестанет срабатывать без ошибки |

**Весь код ниже — черновой. Имена объектов, реквизитов и табличных частей [ПРОВЕРИТЬ] в конфигураторе вашей базы.**

# БЛОК 3. ОРГАНИЗАЦИОННАЯ ЧАСТЬ

> **Маркеры технической реализуемости:**
> **[КОРОБКА]** — типовой механизм 1С:ДО 2.1, включается без настройки под задачу;
> **[НАСТРОЙКА]** — делает администратор 1С:ДО в режиме «Предприятие», без изменения конфигурации;
> **[ДОРАБОТКА]** — требуется 1С-программист (изменение конфигурации/расширение);
> **[ПРОВЕРИТЬ]** — формулировка описывает механизм по смыслу; точное наименование команды, отчёта, роли или реквизита нужно сверить в вашей базе до подписания.
>
> **Правило работы с этим документом:**
> 1. Все наименования разделов, отчётов, ролей и реквизитов 1С даны **функционально, а не как путь по меню**. Пути по меню различаются между вариантами поставки (ПРОФ / КОРП / ДГУ) и релизами 2.1.x — сверять обязательно.
> 2. Все числовые пороги (проценты, количество дней, размер выборки) — **управленческая гипотеза на первый квартал работы**, а не расчётная норма. Помечены словом *(гипотеза)*. Пересматриваются по фактической статистике через 3 месяца.
> 3. Номера приказов, ЛНА, ФИО, наименования подразделений — плейсхолдеры `___`. **Не вписывать реальные реквизиты до подтверждения ответственным за ЛНА.**
> 4. Из нормативных ссылок оставлены только два федеральных закона, которые проверяемы и точно относятся к предмету. Любые отраслевые приказы и правила добавляет юридическая служба **со своей проверкой действующей редакции** — в шаблоне для них оставлено пустое место.

# ЧАСТЬ 2. РОЛЬ КОНТРОЛЁРА

## Контролёр как внутренняя вакансия

Регламент и должностная инструкция объясняют, **что человек обязан делать**. Они не объясняют, **зачем ему соглашаться**. Поэтому, прежде чем нести приказ, покажите будущему контролёру вот такой текст на полстраницы — он написан в формате вакансии и читается совершенно иначе, чем перечень обязанностей.

Разница именно в двух последних блоках: «что даёт» и «как согласиться» в регламент не пишут, а они и превращают дополнительную нагрузку в позицию.

> ### Контролёр заявок на доступ к ресурсам
> Внутренняя роль, совмещение с основной работой
>
> **Что делать**
> - 15 минут утром — открыть список просроченных заявок и разобраться, у кого встало;
> - раз в неделю по понедельникам — сверить с кадровой службой уволенных и переведённых, отозвать лишние доступы;
> - раз в месяц — собрать три цифры для руководителя: средний срок, максимальный, доля просрочек;
> - вмешиваться, когда заявка висит: переназначить исполнителя, продлить срок с комментарием, вернуть на доработку.
>
> **Что нужно**
> - знание процесса согласования и людей в нём;
> - доступ на просмотр всех заявок и отчётов — выдаётся приказом, а не «по договорённости»;
> - готовность звонить и спрашивать «почему стоит». Это половина работы.
>
> **Что даёт**
> - полномочия закреплены приказом, а не «попросили присмотреть»;
> - вы первым видите, где процесс рвётся, — и это ваш аргумент на любом совещании;
> - заместитель назначается сразу, поэтому отпуск не ломает работу и не ложится на вас в двойном объёме.
>
> **Как согласиться:** ответить на служебную записку № [___] до [__.__.____].

**Что здесь важно не потерять при переписывании под себя.**

| Блок | Ошибка, которая убивает текст |
|---|---|
| Что делать | Список без времени. «Контролировать сроки» пугает, «15 минут утром» — нет |
| Что нужно | Забыть про права. Роль без прав на просмотр всех заявок не работает, и человек это поймёт на второй день |
| Что даёт | Пропустить целиком. Это самый частый промах: текст превращается в список нагрузок |
| Как согласиться | Оставить открытым. Без срока и адресата ответа не будет |



## 2.1. Кого назначить

| Кандидат | За | Против | Решение |
|---|---|---|---|
| **Делопроизводитель архива** | Ежедневно в 1С:ДО; контроль сроков — родственная функция; не владелец ресурсов и не выдаёт доступ технически (нет конфликта интересов); не требует новой штатной единицы | Может не хватить веса, чтобы «продавить» согласующих-руководителей; при перегрузке контроль формализуется | **Основной Контролёр** |
| **Специалист по ИБ** | Авторитет, понимание рисков, интерес к качеству обоснований | Сам участник этапа 4 — контролировал бы себя; в 1С:ДО заходит редко | **Методолог**: раз в квартал проверяет качество решений, ежедневный контроль не ведёт |

**Правила эскалации, закрепляемые письменно:**

1. Эскалация — процедура, а не конфликт. Контролёр фиксирует факт нарушения срока и не оценивает качество работы исполнителя.

3. На каждом уровне информируется заявитель — именно это закрывает исходную проблему «не видно, что происходит с заявкой».

## 3. Расчёт эффекта

> **Все числа в примере 3.3 — учебные и условные.** Они показывают, как считается формула. Подставьте свои. Чужие числа на защите = проваленный доклад.

### 3.1. Переменные

| Обозн. | Переменная | Где взять | Ваше значение |
|---|---|---|---|
| `N` | Заявок на доступ в месяц | Список документов вида «Заявка…» за 3 полных месяца ÷ 3 `[ПРОВЕРИТЬ]` название отчёта/отбора в вашей базе | ______ |
| `T` | Средний срок прохождения заявки, раб. дн. | Отчёт по срокам исполнения процессов/задач `[ПРОВЕРИТЬ]` | ______ |
| `Tmax` | Максимальный срок, раб. дн. | Тот же отчёт | ______ |
| `ΔT` | На сколько сократим `T` | **Гипотеза**, берите скромно | ______ |
| `Z` | Обращений «где моя заявка» на 1 заявку | Ручной подсчёт 2 недели (см. лист ниже) | ______ |
| `tz` | Минут на 1 обращение (спросил + отвлёк + ответил) | Замер | ______ |
| `P0` | Доля возвратов на доработку сейчас | Подсчёт | ______ |
| `P1` | Доля возвратов после проекта | **Гипотеза** | ______ |
| `tp` | Минут на один цикл возврата | Замер | ______ |
| `C` | Стоимость часа сотрудника, ₽ | ФЭО/бухгалтерия (оклад + налоги + накладные ÷ часы) | ______ |
| `k` | Доля рабочего времени, теряемая без доступа (0…1) | **Гипотеза**, берите скромно | ______ |
| `H` | Часов в рабочем дне | 8 | 8 |

**Лист учёта `Z` — распечатать и повесить у себя, у ИТ и у секретаря на 2 недели:**

| Дата | Кто спросил (подразделение) | Канал (звонок / письмо / пришёл) | Минут | Подпись принявшего |
|---|---|---|---|---|
|  |  |  |  |  |

`Z` = число строк ÷ число заявок за тот же период. На защите так и говорите: **«замеряли две недели вручную»** — это ваш собственный факт, и он сильнее любой красивой оценки.

### 3.2. Формулы

**Э1 — вопросы «а где моя заявка» (твёрдая):**
```
Э1_мес = N × Z × (tz / 60) × C
Э1_год = Э1_мес × 12
```

**Э2 — сокращение возвратов на доработку (твёрдая):**
```
Э2_мес = N × (P0 − P1) × (tp / 60) × C
Э2_год = Э2_мес × 12
```

**Э3 — простой сотрудника без доступа (мягкая, показывать отдельно):**
```
Э3_мес = N × ΔT × k × H × C
Э3_год = Э3_мес × 12
```

**Затраты:**
```
З = часы_внутренние × C + часы_программиста × ставка_программиста + прочее
```

**Окупаемость — только по твёрдой экономии:**
```
Срок_окупаемости_мес = З / (Э1_мес + Э2_мес)
```

### 3.3. Пример — ЦИФРЫ УСЛОВНЫЕ, УЧЕБНЫЕ

| Переменная | Условное значение |
|---|---|
| `N` | 120 заявок/мес |
| `Z` | 0,8 обращения на заявку |
| `tz` | 12 мин |
| `P0 → P1` | 20 % → 10 % |
| `tp` | 40 мин |
| `C` | 800 ₽/час |
| `ΔT` | 1,5 раб. дня |
| `k` | 0,10 |

| Показатель | Расчёт | В месяц | В год |
|---|---|---|---|
| **Э1** вопросы о статусе | 120 × 0,8 × 0,2 ч × 800 | **15 360 ₽** | **184 320 ₽** |
| **Э2** возвраты на доработку | 120 × 0,10 × 0,667 ч × 800 | **6 400 ₽** | **76 800 ₽** |
| **Твёрдая экономия** | Э1 + Э2 | **21 760 ₽** | **261 120 ₽** |
| Э3 простой без доступа *(мягкая)* | 120 × 1,5 × 0,1 × 8 × 800 | *115 200 ₽* | *1 382 400 ₽* |

**Затраты (условные):** 60 ч внутренних × 800 ₽ = 48 000 ₽ + 40 ч программиста × 3 000 ₽ = 120 000 ₽ → **168 000 ₽**.
**Окупаемость:** 168 000 ÷ 21 760 ≈ **7,7 мес.**

### 3.4. Четыре правила, которые спасут вас на защите

1. **Твёрдое и мягкое — разными строками.** Э3 давайте серым, мелким, с подписью «оценочно, в окупаемость не включено». Включите 1,38 млн в окупаемость — первый же финансист разберёт расчёт, и рухнет весь доклад.
2. **Не называйте высвобожденное время экономией бюджета.** Готовая формулировка: *«Это высвобожденное рабочее время, а не сокращение затрат. Оно возвращается в основную работу подразделения»*. Скажете это сами — снимете половину вопросов ФЭО.
3. **Гипотеза называется гипотезой.** На слайде прямо: «значения оценочные, уточняются по итогам замера, срок — 5 рабочих дней».
4. **Обещайте пересчёт.** «Через 30 дней после запуска приношу фактические цифры». Спор о цифрах превращается в отложенный вопрос — а к тому моменту у вас факт.

## 7. Оформление как проекта цифровой трансформации

### Паспорт

**Официальное название:**
> «Прозрачный доступ: цифровизация процесса предоставления доступа к ресурсам и архивным фондам»

**Рабочее:** «Прозрачная заявка».

**Цель (одно предложение):**
> Обеспечить прослеживаемость жизненного цикла заявки на доступ к ресурсам — от подачи до выдачи и возврата прав — с автоматическим информированием заявителя и контролем сроков, на базе действующей 1С:Документооборот 2.1, без внедрения новых информационных систем.

### KPI — берите 4–5, не больше

| KPI | Как считается | База «до» | Цель *(гипотеза до замера)* |
|---|---|---|---|
| Средний срок прохождения заявки | отчёт по процессам, раб. дн. | замер понедельника | −30 % |
| Доля просроченных сверх норматива | просроченные ÷ всего | замер | ≤ 10 % |
| Доля возвратов на доработку | `P0` | замер | ≤ 10 % |
| Обращений «где моя заявка» на 100 заявок | лист учёта | замер | −70 % |
| Доля заявок с полным заполнением обязательных полей | заполненные ÷ всего | замер | ≥ 95 % |
| *(для ИБ)* Доля доступов с зафиксированным сроком действия | подсчёт по реквизиту | замер | ≥ 90 % |

**Железное правило:** KPI без зафиксированного значения «до» не принимается. Целевые значения в этой таблице — **гипотезы**, подпишите их так на слайде и уточните после замера.

### Этапы

| Этап | Содержание | Маркер | Срок | Бюджет |
|---|---|---|---|---|
| **0. Замер** | Фиксация «как есть», базовые значения KPI | `[КОРОБКА]` | 1 нед | 0 ₽ |
| **1. Победа за неделю** | Уведомления, обязательные поля, контролёр, регламент | `[НАСТРОЙКА]` | 1 нед | 0 ₽ |
| **2. Карточка и отчётность** | Полное использование полей карточки, регулярные отчёты, дайджест согласующим | `[НАСТРОЙКА]` `[ПРОВЕРИТЬ]` | 2–4 нед | внутренние часы |
| **3. Внешняя прозрачность** | Страница статуса по ссылке, свои тексты писем, контроль возврата прав по сроку | `[ДОРАБОТКА]` | по ТЗ | считать по п.3 |
| **4. Тиражирование** | Тот же подход на другие процессы архива | `[НАСТРОЙКА]` + `[ДОРАБОТКА]` | после этапа 3 | — |

### Структура отчёта на 30-й день (1 страница)

1. **Что было.** «Заявитель не мог узнать статус, не обращаясь к сотрудникам. Средний срок ___ раб. дн., максимальный ___».
2. **Что сделали.** 4–6 пунктов, каждый глаголом совершенного вида: включили, настроили, назначили, регламентировали. Обязательно: «без приобретения ПО и лицензий, силами сотрудников архива».
3. **Что стало.** Таблица KPI «до / после / изменение». Только замеренное.
4. **Эффект.** Твёрдая экономия по формулам; мягкая — отдельной строкой с пометкой «оценочно».
5. **Качественные результаты.** Прозрачность, доказуемость выдачи прав, снижение нагрузки на ИТ, готовность к проверке.
6. **Что дальше.** Этап 3 с оценкой трудозатрат, ТЗ приложением.
7. **Приложения.** Скриншот уведомления, регламент контролёра, выгрузка отчёта по срокам.

### Формулировки для отчётности по цифровой трансформации

- «Переход от информирования по запросу к проактивному информированию заявителя».
- «Обеспечена сквозная прослеживаемость жизненного цикла заявки».
- «Введён контроль сроков с персональной ответственностью».
- «Развитие функциональности действующей информационной системы без расширения ИТ-ландшафта».
- «Достигнута измеримость процесса: зафиксированы базовые и целевые значения показателей».

## 8. Готовые тексты для копирования

### 8.1. Письма заявителю — не больше трёх на заявку

Квадратные скобки — подставляемые значения; проверьте, какие из них доступны в шаблоне вашей базы `[ПРОВЕРИТЬ]`.

**Письмо 1. Заявка принята**
> Тема: Заявка на доступ № [номер] — принята
>
> Здравствуйте, [имя отчество]!
> Ваша заявка № [номер] от [дата] на доступ к ресурсу «[ресурс]» принята в работу.
> Плановый срок рассмотрения — [дата].
> Посмотреть текущий статус: [ссылка]
> Отвечать на это письмо не нужно. Вопросы по заявке — [контакт контролёра].

**Письмо 2. Решение принято**
> Тема: Заявка на доступ № [номер] — [согласована / отклонена / возвращена на доработку]
>
> Здравствуйте, [имя отчество]!
> По вашей заявке № [номер] принято решение: **[решение]**.
> [Если возврат:] Что требуется исправить: [комментарий].
> [Если отклонение:] Основание: [комментарий].
> Открыть заявку: [ссылка]

**Письмо 3. Доступ предоставлен**
> Тема: Заявка на доступ № [номер] — доступ предоставлен
>
> Здравствуйте, [имя отчество]!
> Доступ к ресурсу «[ресурс]» предоставлен [дата].
> Срок действия доступа — до [дата]. За [N] дней до окончания придёт напоминание.
> Заявка: [ссылка]

**Правило содержания:** в письмо идут только номер, статус, ресурс, срок и ссылка. Логины, пароли, содержимое доступа, персональные данные — никогда. Согласуйте эти три текста с ИБ до презентации.

### 8.2. Регламент контролёра сроков — на одну страницу

> **Регламент контроля сроков по заявкам на доступ к ресурсам**
> Утверждён: `[распоряжение № ___ от __.__.____ — заполнить по факту]`
>
> **1. Контролёр:** [ФИО, должность]. Замещающий: [ФИО].
> **2. Что смотрит:** перечень заявок в работе и просроченных сверх норматива [указать норматив, раб. дн.].
> **3. Как часто:** ежедневно до [время]; в отсутствие — замещающий.
> **4. Действия при просрочке:**
> — 1-й рабочий день просрочки: напоминание исполнителю/согласующему;
> — 2-й: письмо исполнителю с копией его руководителю;
> — 3-й: эскалация [ФИО, должность].
> **5. Отчётность:** еженедельно — сводка «принято / выдано / просрочено» руководителю архива. Первый месяц сводка обезличена до уровня подразделения.
> **6. Что контролёр НЕ делает:** не принимает решения по существу заявки, не согласовывает и не выдаёт доступ.

### 8.3. Служебная записка / письмо руководителю на согласование этапа 1

> Прошу согласовать проведение этапа 1 проекта «Прозрачная заявка» — развитие действующего процесса «Заявка на доступ к ресурсам» в 1С:Документооборот 2.1.
> Содержание этапа: включение автоматических уведомлений заявителю, установка обязательных полей карточки заявки, назначение контролёра сроков и утверждение регламента контроля.
> Срок — 5 рабочих дней. Бюджет — 0 ₽, приобретение ПО и лицензий не требуется, работы выполняются силами архива.
> По итогам этапа будут представлены фактические значения показателей «до»: средний и максимальный срок прохождения заявки, доля возвратов на доработку.
> Прошу дополнительно закрепить роль контролёра сроков за [ФИО, должность].

| Ссылки на НПА, приказы, положения | **в пакете отсутствуют намеренно** | реквизиты вписывает архив / юрслужба |
| Любые сведения об ОЭЗ «Алабуга»: структура, роли, регламенты, фамилии | **в пакете отсутствуют** | заполняется по итогам интервью и по документам на руках |
